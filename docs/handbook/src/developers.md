# For developers

These documents live in the repository rather than in this handbook:

- [`CONTRIBUTING.md`](https://github.com/openlinuxsystems/orthros/blob/main/CONTRIBUTING.md):
  how to build and test, and what a change needs before it merges.
- [`CODE_OF_CONDUCT.md`](https://github.com/openlinuxsystems/orthros/blob/main/CODE_OF_CONDUCT.md),
  [`GOVERNANCE.md`](https://github.com/openlinuxsystems/orthros/blob/main/GOVERNANCE.md)
  and [`SECURITY.md`](https://github.com/openlinuxsystems/orthros/blob/main/SECURITY.md):
  how people work together, who decides, and how to report a vulnerability.
- [`docs/coding-standard.md`](https://github.com/openlinuxsystems/orthros/blob/main/docs/coding-standard.md):
  rules for Rust code, including where `unsafe` is allowed.
- [`docs/adr/`](https://github.com/openlinuxsystems/orthros/tree/main/docs/adr):
  architecture decision records.
- [`docs/roadmap.md`](https://github.com/openlinuxsystems/orthros/blob/main/docs/roadmap.md):
  the implementation plan, phase by phase.

- [`docs/design/`](https://github.com/openlinuxsystems/orthros/tree/main/docs/design):
  how the kernel works, starting with `boot.md`, `interrupts.md`,
  `memory.md`, `random.md`, `capabilities.md`, `scheduler.md` and
  `ipc.md`.

The kernel's source documentation is generated by rustdoc. The kernel
builds for its own target with `core` compiled from source (ADR 0011), so
rustdoc needs the same flags as `ob build`:

```sh
cargo doc --manifest-path kernel/Cargo.toml --target-dir target/kernel \
    --target kernel/targets/x86_64-radix-kernel.json -Zjson-target-spec \
    -Zbuild-std=core,compiler_builtins,alloc \
    --workspace --exclude radix-arch-aarch64 --no-deps --open
```

The kernel libraries under `kernel/lib/` also build for the host, which is
how `./ob test unit` runs their tests:

```sh
cargo test --manifest-path kernel/Cargo.toml -p radix-acpi
```

The memory manager, `radix-mm`, the capability core, `radix-cap`, the
scheduling policy, `radix-sched`, and the arithmetic of IPC, `radix-ipc`,
also have Kani proof harnesses (ADRs 0019, 0030 and 0032), which
`./ob test kani` checks; they take about ten minutes and need the Kani
release `./ob doctor` names:

```sh
cargo install --locked kani-verifier --version 0.68.0
cargo kani setup
./ob test kani
```

The capability core's derivation tree, retyping and revocation are also
modelled in TLA+ (`kernel/cap/tla/`, ADR 0024), and so are how the
scheduler blocks, wakes and switches threads between CPUs
(`kernel/sched/tla/`, ADR 0030) and how endpoint calls, replies,
cancellation and closing interact (`kernel/ipc/tla/`, ADR 0032).
`./ob test tla` checks the three models with the TLC model checker in
about ten minutes. It needs Java; `ob` downloads the pinned TLA+ tools
itself:

```sh
sudo apt install default-jre-headless
./ob test tla
```

## User programs and the system call interface

The system calls, the methods of every kind of object and the kernel's
errors are defined once, in `abi/*.ridl` (ADR 0033). `tools/ridlc`
compiles them into the Rust bindings of `radix-abi`, the C headers that
`./ob build` installs under `out/sysroot/include/radix/`, and the
section 2 man pages that `./ob docs` builds; `ridlc` also runs on its own:

```sh
cargo run -p ridlc -- abi --c out/include --man out/man2
```

The user programs are a workspace of their own, `userspace/`: `libradix`
(entry, system calls, printing, rings and channels) and `usertests`, the
image of test and benchmark programs that the kernel's `user`, `ipc` and
`bench` self-tests start (ADR 0036). `./ob build` builds them with the
kernel; `./ob test boot --case user`, `--case ipc` and `--case fuzz` run them;
`fuzz` makes random system calls from seeds it logs, and
`fuzz-seed=N` on the kernel command line repeats a run (ADR 0043).
`./ob bench` measures system calls, IPC round trips, context switches,
fresh pages, TLB shootdowns and memory copies on Radix and the closest
operations of Linux in a virtual machine set up the same way, and writes
a report to `out/bench/report.md` (ADR 0039). It needs KVM, and a Linux
kernel it may read: on Debian, Ubuntu and Mint, copy your own once with
`sudo install -m 644 /boot/vmlinuz-$(uname -r) .cache/vmlinuz` and run
`./ob bench --linux-kernel .cache/vmlinuz`. It measures both systems
three times in turn and keeps each operation's fastest run (ADR 0046).
CI runs it with `--gate` on every pull request and merge, and fails if
Radix is slower than Linux at any operation. `./ob bench --instructions` needs neither: it counts the
instructions each operation takes under QEMU, and with `--gate` fails if
one on one CPU goes over its budget in `tools/xtask/src/bench.rs`, as CI
does (ADR 0045). A change that needs more raises the budget in the same
pull request and says why. How it all works is in `docs/design/ipc.md`
and `radix-ipc(7)`.
